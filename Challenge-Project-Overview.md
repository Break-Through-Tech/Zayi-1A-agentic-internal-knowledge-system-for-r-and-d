## 🎯 The Challenge

### Project Summary
In this project, you will use a curated subset of publicly available ArXiv Machine Learning research papers and Retrieval-Augmented Generation (RAG) and semantic chunking to build an Internal Knowledge System that extracts, synthesizes, and drafts structured summary memos with citations from complex technical documentation. This will help our company address the time-intensive process of manually parsing dense PDFs and extracting architectural patterns for our R&D pipeline.

### Success Criteria
Success will be measured by a functional local prototype that successfully automates the "Draft Triage Memo" workflow directly within a Google Colab notebook. Quantitatively, the system's performance will be verified against the provided central ground-truth Q&A pairs during the November review phase to track document retrieval accuracy (evaluating if the system successfully fetches the correct PDF pages). A successful outcome by December looks like a structured, cited technical memo generated by the pipeline that consistently provides accurate architectural patterns with minimal human corrections required by the reviewing engineer.

### Stretch Goals

1. Agentic Self-Correction (LangGraph): Upgrading the linear pipeline into an agentic workflow using LangGraph. This introduces an autonomous self-grading loop where an LLM evaluator node reviews the retrieved context and automatically triggers a query-rewriting node to search again if the initial results are deemed irrelevant.    

2. Local Context Reranking: Implementing a lightweight, local cross-encoder model (such as FlashRank) to re-rank retrieved PDF chunks within the Colab environment. This optimizes context relevance for the generator without incurring any additional Gemini API calls.   

3. Deterministic Evaluation Scripting: Building a local evaluation pipeline to benchmark the agent against the provided ground-truth dataset using rule-based metrics (like keyword containment verification and ROUGE/BLEU scores). This avoids the heavy token costs and daily quota depletion of LLM-as-a-judge frameworks.   

4. Gradio UI Prototyping: Developing a lightweight browser interface using Gradio to map out the Human-in-the-Loop approval step. Gradio's simple state management minimizes the script re-rendering risks that typically cause accidental API call overruns.   
   
### Project Milestones

Use these milestones to guide your work. Your team will create a **GitHub Projects board** to track tasks within each milestone.

| Month | Milestone | Key Activities |
|---|---|---|
| September | Data Exploration & Preprocessing | Complete exploratory data analysis (EDA) on the ArXiv dataset. Implement PDF text cleaning, test semantic chunking strategies, and successfully embed and store the data into a local ChromaDB vector database. |
| October | Modeling & Orchestration | Build a baseline linear RAG pipeline using LangChain and the Gemini API to retrieve documents and answer queries. Implement robust API error handling and exponential backoff strategies (e.g., using the tenacity library) to manage rate limits. |
| November | Evaluation & Hyperparameter Tuning | Systematically evaluate the baseline RAG pipeline's output against the provided ground-truth Q&A dataset. Students will test different chunk sizes, overlap thresholds, and retrieval parameters (k-values) to optimize document retrieval accuracy and minimize hallucinations. |
